# Kirara AI 3.3.0a7 精湛化与可替代性改造设计

## 状态

- 目标版本：`3.3.0a7`
- 基线：项目 A `E:\output\kirara-ai\kirara-ai3.3.0a4`
- 改造对象：项目 B `E:\output\kirara-ai\kirara-ai3.3.0a5`
- 设计状态：已批准，进入实施
- 兼容要求：项目 B 必须完整覆盖项目 A 的既有功能；新增能力只能正向提升，不能降低行为、稳定性或可理解性

## 1. 目标与非目标

### 1.1 目标

1. 修复工作流切换、模型目录刷新、规则持久化和注册表读取中的并发与事务问题。
2. 缩短首次打开工作流和大型画布的可交互时间，避免布局导致节点重叠、字体覆盖和连线遮挡。
3. 将现有主题提升为可维护的设计系统，覆盖明暗主题、状态、焦点、对比度、响应式和高对比模式。
4. 让内置工作流与触发规则在首次部署后可发现、可解释、可自检、可直接复制使用，且不复活用户明确删除的预设。
5. 在不另造执行引擎的前提下，以现有 Block、Workflow、Plugin、EventBus、MCP 和 DispatchRule 为基础，提供受控的 Agents、Skills、Hooks 和 MCP 扩展路线。
6. 统一所有发布身份为 `3.3.0a7`，证明清洁环境构建、wheel/sdist、Docker、迁移和 A 到 B 的替代性。

### 1.2 非目标

- 不重写工作流执行引擎，不改变既有工作流 YAML 的语义。
- 不删除或重命名现有公开 API、函数变量、配置键、事件名、注释和插件入口。
- 不默认开放任意 shell、文件系统、网络或 MCP 工具权限。
- 不为了“Agents/Skills/Hooks”命名而加入无法验证的空壳运行时。
- 不把用户数据、工作流、规则、插件配置或敏感配置迁移到不可逆的新格式。

## 2. 兼容契约

### 2.1 必须保持

- A 中存在的工作流、规则、聊天命令、私聊、群聊、@、fallback 记忆、帮助、清空记忆、骰子和抽卡行为。
- 旧规则格式转换、新规则格式、规则优先级和首条匹配语义。
- 工作流根据接口提取模型后，用户仍可手动在下拉菜单选择模型。
- 自动定期刷新模型目录，但刷新不能改写工作流中的 `model_name`、fallback 槽位或用户草稿。
- 静态 Block 元数据缓存、动态模型 options 刷新、连线类型索引、Promise 去重、API 故障降级、Monaco 异步加载和 pending edit flush。
- undo/redo 独立存在，自动排布可撤销，用户删除的预设和规则不被后续启动复活，用户修改的预设不被覆盖。
- 既有插件发现、加载、启动、停止、禁用、MCP 服务管理以及所有现有 API 路径。

### 2.2 允许新增

- 内部辅助函数、锁、事务日志、恢复器、revision/CAS 字段、快照 API、性能指标和测试工具。
- 可选的工作流健康状态、规则预览结果、扩展 manifest 字段、权限声明和可观测事件。
- 对旧配置的只读兼容解析和一次性升级提示；禁止静默改变用户选择。

## 3. 可靠性与持久化

### 3.1 事务模型

新增内部事务协调器，位于 workflow/dispatch 持久化边界，不改变现有 registry 对外方法。

每次涉及多个文件的操作按以下阶段执行：

1. 在同目录创建暂存文件，写入 UTF-8 内容并 `flush`、`fsync`。
2. 解析暂存文件并做 schema、ID、路径和引用校验。
3. 写入事务日志，记录操作 ID、目标文件、旧文件摘要、新文件摘要和阶段。
4. 用同目录原子替换完成提交；每一步都更新日志。
5. 所有目标替换成功后更新内存注册表和 tombstone 状态。
6. 清理日志与暂存文件；清理失败只记录告警，不回滚已提交内容。

启动时扫描未完成事务：

- 所有新摘要已存在：补完成内存加载并清理日志。
- 所有旧摘要仍存在：删除暂存文件并清理日志。
- 状态不一致：保留原文件，隔离损坏暂存文件，给出明确错误和恢复路径；禁止猜测性覆盖。

### 3.2 注册表快照

`WorkflowRegistry` 和 `DispatchRuleRegistry` 暴露受锁保护的只读快照方法。API 列表、健康检查和规则预览只读取快照，不访问私有字典。快照包含稳定排序、revision 和加载错误摘要，避免并发迭代异常及混合版本响应。

### 3.3 请求代次与 CAS

工作流编辑器为每次加载、保存、校验和导入生成 generation。异步响应必须同时通过 generation、当前 workflow ID 和 revision 检查。旧响应只可更新日志，不可更新画布、草稿或持久化文件。

模型目录刷新为“目录写入 CAS”：记录适配器实例 ID 和配置指纹，只有两者未变化时才提交目录。下线模型保留用户当前值并标记状态，不自动替换。

### 3.4 错误呈现

所有事务、恢复、校验、MCP、模型目录和布局错误都转换为用户可理解的状态：正在恢复、配置已保留、某工具不可用、某节点需要重新选择模型。日志中保留错误 ID、操作 ID 和关联 workflow ID，禁止输出密钥。

## 4. 画布性能与智能布局

### 4.1 加载分层

打开工作流分为：

1. 立即渲染轻量节点骨架和已保存位置。
2. 异步合并静态 Block 元数据和动态模型 options。
3. 仅对缺失或明显非法坐标的节点做增量布局。
4. 在浏览器空闲时间完成非阻塞碰撞修正。

已有完整坐标且无重叠的工作流禁止自动 dagre 重排。用户主动点击自动布局时才对全图布局，并把结果作为一个可撤销历史步骤。

### 4.2 布局算法

- 保留现有 dagre 作为有向初排依据，拆成测量、初排、碰撞修正、连线优化四个阶段。
- 使用按网格桶或 R-tree 的空间索引查询候选碰撞，避免全量两两比较。
- 节点尺寸来自实际 DOM 测量；字体加载完成前使用稳定估计值，完成后只对受影响节点重新测量。
- 固定最小节点间距、端口安全边距和标题/状态区高度；修正结果必须可重复。
- 优先沿空闲方向移动节点；发生连线交叉时以局部代价最小为准，不移动用户锁定节点。
- 对无坐标、重复坐标和极端坐标提供诊断，而不是静默跳到不可见位置。

### 4.3 交互改进

- 工具栏提供图标加 tooltip 的适应视图、缩放、撤销、重做、自动布局、对齐、水平/垂直分布、锁定布局和布局预览。
- 多选后显示轻量上下文工具条；无选择时不占用画布空间。
- 布局预览先显示 ghost positions，用户确认后一次性提交历史记录。
- 节点配置面板采用固定宽度约束、可调整分栏和窄屏抽屉，禁止覆盖节点文字或遮住保存操作。
- 连线标签、端口和错误徽标在最小缩放时降级为图标，放大后恢复文字。
- 快捷键、键盘焦点、框选、Shift 多选、复制粘贴、重复、删除和 Escape 取消操作保持可用。

### 4.4 大图预算

建立性能基准：100、300、600、1000 节点，包含缺失坐标、长标题、多端口和大量连线。记录首次可交互时间、布局耗时、主线程阻塞、内存峰值、拖拽帧率和保存延迟。目标是普通工作流打开不因布局阻塞交互，大图布局超过预算时显示进度并允许取消。

## 5. 视觉设计系统

### 5.1 Token 分层

将颜色、间距、圆角、阴影、字号、行高、焦点环和动效拆成基础 token、语义 token 和组件 token。主题不再在组件中散落硬编码颜色。

语义状态至少包含：背景、表面、边框、主文字、次文字、链接、焦点、成功、警告、错误、信息、节点输入、节点输出、选中、锁定、禁用和运行中。浅色与深色必须分别通过对比度检查；不使用单一蓝紫或单一暗色调覆盖全部界面。

### 5.2 可访问性

- 所有图标按钮有可读 `aria-label` 和 tooltip；纯装饰图标隐藏于辅助技术。
- 键盘焦点始终可见，焦点环不被节点阴影吞掉。
- 文本、按钮、节点状态和连线类型满足 WCAG AA 对比度；错误不能只用颜色表达。
- 画布提供节点列表和选中节点摘要，辅助技术用户能通过列表定位节点。
- `prefers-reduced-motion` 下禁用非必要动画；窄屏、200% 缩放和高对比模式不截断操作。

### 5.3 响应式

桌面优先保留画布与配置双栏；中等宽度自动折叠次要工具；移动端把节点列表和配置面板改为抽屉，主操作始终可见。所有按钮、标签、节点标题采用稳定尺寸和可换行约束，避免文字覆盖。

## 6. 首次部署与内置能力

### 6.1 部署自检

启动后提供只读健康检查：版本一致性、数据目录权限、配置 schema、数据库/Alembic、规则可达性、工作流引用、插件状态、MCP 连接和模型目录。自检失败只阻止依赖该项的操作，不阻止用户查看和修复其他配置。

### 6.2 内置工作流分层

保留现有内置系统工作流和 11 个随包模板，新增元数据而不是复制模板：用途、适用模型、所需插件、MCP 权限、输入输出、触发示例、风险和验证步骤。

推荐整理为以下可发现类别：

- 基础聊天：普通聊天、记忆聊天、纯文本稳定输出。
- 系统操作：帮助、清空记忆、健康检查和规则试运行。
- 工具能力：MCP 工具调用、结构化输出和失败回退。
- 自动化：时间感知、定时/事件触发和通知前确认。
- 开发研究：代码解释、文档摘要、检索增强和可观测追踪。

每类只保留一条明确的主路径；功能相近模板通过可选节点或说明区分，避免“函数调用”和“MCP 工具调用”在首次使用时互相误导。

### 6.3 规则可理解性

规则页增加命中预览、优先级冲突、被遮蔽规则、目标工作流缺失、默认 fallback 和最近一次命中信息。保存前只读试运行，不发消息、不执行工作流、不修改数据。规则删除或目标工作流删除时阻止产生不可达引用，并给出迁移选择。

## 7. Agents、Skills、Hooks 与 MCP

### 7.1 设计原则

不新增第二个执行引擎。Agent 是具名、受限的工作流编排配置；Skill 是插件 manifest 声明的 Block、模板、示例和依赖集合；Hook 是类型化、只读、超时隔离的生命周期事件；MCP 是已有 MCPServerManager 的受控能力来源。

### 7.2 最小接口

- Agent manifest：ID、版本、入口 workflow、最大步骤数、超时、会话作用域、工具白名单、人工确认策略。
- Skill manifest：ID、版本、提供的 Block/模板/规则、依赖、权限、迁移和卸载影响。
- Hook：`before_run`、`after_run`、`on_error`，事件载荷只含关联 ID、摘要、耗时和可脱敏结果；hook 不得修改主链路，不得读取密钥。
- MCP：服务配置、连接状态、工具/资源/prompt 能力清单、超时、调用审计和最小权限；默认停用新服务。

所有字段可选且有默认值，旧插件没有 manifest 时继续使用现有加载路径。新能力必须有禁用开关、超时、异常隔离和健康状态。

### 7.3 不加入

- 任意循环自主 Agent、默认联网、任意 shell 执行、隐式文件访问、未经确认的写操作。
- 只显示“智能体”按钮却无法解释调用了哪个工作流、模型、工具和权限的黑盒功能。
- 与现有 Block、Workflow、EventBus 重复的另一套插件运行时。

## 8. 可观测性

为一次消息建立关联 ID，串联规则命中、工作流、节点、LLM 请求、模型目录、MCP 工具和 hook。默认记录低敏摘要、状态、耗时和错误 ID；完整请求内容继续受现有设置控制。提供事件计数、失败率、超时、布局耗时、模型刷新丢弃次数和事务恢复次数。日志脱敏，禁止密钥、令牌和完整敏感内容进入默认日志。
