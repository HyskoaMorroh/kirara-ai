# Kirara AI 3.3.0a7 升级清单

本文是 `3.3.0a7` 发布周期使用的冻结迁移记录，保留当时的目标版本与核对项。当前版本的通用流程见 [升级指南](UPGRADING.md)；不要把本文件中的历史目标版本当作当前安装版本或新的版本源。

## 1. 预升级备份

1. 记录旧版本、启动参数、数据目录、容器镜像标签和卷挂载；不要记录密钥值。
2. 登录旧实例，从「系统设置 -> 备份与恢复」导出 `.kirara-backup.zip`；也可调用备份导出接口。
3. 停止旧服务，确认没有进程继续写入旧数据目录。
4. 将整个 A 数据目录复制到独立、受限的位置，例如 `E:\backup\kirara-data-before-3.3.0a7`。使用复制，不要移动或覆盖 A。
5. 检查备份包可被备份检查接口读取，且副本包含配置、工作流、规则、数据库、记忆、媒体和插件目录。

备份包可能包含 API Key、机器人令牌、Web 密钥和密码哈希，不得提交到 Git、上传到公开制品库或发给他人。

## 2. 安装并启动 3.3.0a7

安装 `3.3.0a7` 后，把 A 数据目录的副本挂载或复制给新实例 B。保留旧程序、旧数据和备份，直到验收完成。首次启动可能生成缺失的 Web 密钥，因此必须在副本上试升。

## 3. readiness 检查

登录 B 后调用受保护的 readiness 接口，确认以下检查通过或处于预期的跳过/警告状态：

- 数据目录可写
- 配置可解析
- 工作流有效
- 调度目标存在
- IM、LLM 与可选 MCP 状态符合现场预期

readiness 只提供本地诊断，不保证远端 LLM 或 MCP 此刻一定可用，也不会回显密钥。

## 4. 无副作用验证

### 工作流

列出工作流，确认自定义工作流、已编辑预设和手工节点坐标仍在。对关键工作流提交完整定义进行静态校验，确认没有未知区块或端口、重复输入连线、缺失入口、不可达节点或非受控环。静态校验不得保存、执行或自动改图。

### 调度

用真实的测试消息调用 dispatch preview，确认 `/help`、记忆清理、骰子、抽卡、群聊 `/chat`、私聊和兜底记忆仍指向预期工作流；再调用 dispatch reachability 检查规则遮蔽。preview 和 reachability 都不应执行工作流、发送消息或保存规则。

### 模型下拉框和手工选择

在 WebUI 打开每个关键工作流，逐项核对主模型和最多四个备用模型槽位仍保持升级前的手工选择。模型目录刷新只允许更新目录，不得改写这些槽位；模型下拉框必须仍能显示并选择现场使用的模型。

### 周期刷新观察

观察一次模型目录周期刷新及其日志，确认刷新失败会回滚运行时状态，刷新成功只更新模型目录；刷新前后重新核对主模型和备用槽位。远端探测可能产生费用或写入状态，执行前确认供应商、费用和变更窗口。

## 5. 回滚和备份恢复

任一 readiness 关键检查失败、工作流/规则缺失、已删预设复活、模型槽位改变或真实消息行为不一致时，停止放量：

1. 停止 B，避免继续写 B 数据。
2. 保存脱敏日志和 B 数据副本，不覆盖 A 备份。
3. 恢复旧程序版本及原启动参数。
4. 优先挂回未被 B 写过的 A 数据副本；或在空数据目录中导入升级前备份。导入会写数据并先创建自动回滚包，必须人工确认。
5. 导入成功后按响应要求完整重启，再重新运行 readiness、工作流静态校验、调度 preview/reachability 和模型手工选择核对。

新旧进程不得同时指向同一个数据目录，也不要手工拼接新旧规则、tombstone 或工作流文件。
